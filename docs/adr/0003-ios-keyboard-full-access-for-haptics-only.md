# iOS Keyboard asks for Full Access, but only uses it for haptics and sounds

The Keyboard sets `RequestsOpenAccess = YES` and the Companion app's setup steps ask the user to allow Full Access, explaining that it is only for haptics and key-click sounds and that nothing leaves the phone. iOS lets only the user grant it and shows its own fixed warning, so the Keyboard must also work fully without it. Learning and settings stay in the Keyboard's own sandbox whether or not Full Access is granted, so behaviour does not split between users and no data migration is needed later. Settings are therefore edited inside the Keyboard, not in the Companion app. We do not use the network or the shared container that Full Access would unlock; using either would break the promise made on the setup screen.
